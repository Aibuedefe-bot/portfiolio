Describe a system in plain English, get an AWS architecture diagram

Type what you want to build and get back a real AWS architecture diagram, with the official icons and the cloud, VPC, availability zone and subnet boxes drawn around the right services. It saves as a .drawio file, so you open it and edit it, because the first version is never the final version.

The model never decides layout. It returns a flat list of components, each tagged with one word for the zone it belongs to, and Python builds every container from the inside out. A 3B model can't nest a subnet inside the wrong VPC because it is never asked to. It runs on your own machine, so there is no API cost and no design detail leaves your laptop.

FastMCP · Ollama llama3.2:3b · Streamlit · Python 3.11 · draw.io XML
Resultruns locally at zero cost, with every failure case documented from measured runs

Turning written procedures into narrated instructional videos

An agent pipeline that reads a written standard operating procedure and produces a narrated video walkthrough of it. Nobody reads a 12 page procedure document. They will watch two minutes.

The first version worked and took around 500 seconds per video, which meant timeouts and users giving up. I profiled where the time actually went and rebuilt it: better tool selection, tighter prompting, and parallelism where it earned its place. It runs in about 120 seconds now. Building agent demos is easy. Making one cheap enough to leave running is the job.

AWS Bedrock · Claude · Polly · Nova Reel · MediaConvert · Strands Agents
Resultabout 500s to about 120s per video, roughly 4x faster and cheaper per run

How I work

What I'll argue for on your team

So you know what you're getting before you hire me.

  1. Evaluation first, then the feature. If I can't measure whether a change made things better, I'm guessing. So are you.
  2. Boring and running beats clever and half finished. Most of what makes a system reliable is unexciting work nobody claps for.
  3. The limitation goes in the README. Every model has a case it handles badly. Better you hear it from me now than find it in month three.
  4. I write things down. Decisions go somewhere people can find them. I'm five hours ahead of New York, so nobody should be stuck waiting for me to wake up.
  5. Tell me early if I'm wrong. I'd rather redo it on Tuesday than defend it until Friday.

About

Short version

I'm a machine learning engineer in Lagos. I build AI systems on AWS for an AWS partner company, mostly search, retrieval and agents, and I've shipped them into production for clients in banking, aviation and agriculture. I'm AWS Machine Learning certified.

I'm also co-founder and CTO of Ojiffy, a quick commerce marketplace in Lagos. We couldn't hire a field sales agent, so I do the vendor visits myself, four hours a day on foot. It has made me a better engineer. When you've spent the morning trying to get one shop owner to sign up, you stop building things nobody asked for.

You're probably wondering how that fits with a full time role. I've done both since early 2026. The engineering job gets my working hours. I'd give you the same answer in an interview.

I learned core ML before the LLM boom, regression, classification, deep networks, statistics, and I still reach for a boosted tree first when latency, cost or explainability matter. GenAI is a tool in the box, not the box.

I sing soprano. I got tired of practising against a recording with all four parts in it, so I built a model to pull my part out. Most of my projects start as something small that annoys me.
