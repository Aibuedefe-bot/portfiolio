Describe a system in plain English, get an AWS architecture diagram

Type what you want to build and get back a real AWS architecture diagram, with the official icons and the cloud, VPC, availability zone and subnet boxes drawn around the right services. It saves as a .drawio file, so you open it and edit it, because the first version is never the final version.

The model never decides layout. It returns a flat list of components, each tagged with one word for the zone it belongs to, and Python builds every container from the inside out. A 3B model can't nest a subnet inside the wrong VPC because it is never asked to. It runs on your own machine, so there is no API cost and no design detail leaves your laptop.

FastMCP · Ollama llama3.2:3b · Streamlit · Python 3.11 · draw.io XML
Resultruns locally at zero cost, with every failure case documented from measured runs

How I work

What I'll argue for on your team

So you know what you're getting before you hire me.

  1. Evaluation first, then the feature. If I can't measure whether a change made things better, I'm guessing. So are you.
  2. Boring and running beats clever and half finished. Most of what makes a system reliable is unexciting work nobody claps for.
  3. The limitation goes in the README. Every model has a case it handles badly. Better you hear it from me now than find it in month three.
  4. I write things down. Decisions go somewhere people can find them. I'm five hours ahead of New York, so nobody should be stuck waiting for me to wake up.
  5. Tell me early if I'm wrong. I'd rather redo it on Tuesday than defend it until Friday.
