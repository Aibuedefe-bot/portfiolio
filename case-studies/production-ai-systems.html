Production AI systems for banking, aviation and agriculture

The work

I build AI systems on AWS for an AWS partner company. Mostly two shapes: systems that search and reason over a client's own documents, and agents that take actions rather than only answering questions. They go out as infrastructure another engineer can pick up, not as notebooks.

How they're built

Bedrock for models, Lambda for compute, OpenSearch for retrieval, DynamoDB for state, FastAPI at the edge, and Terraform for all of it. Nothing is clicked into existence in a console. If it isn't in code, it doesn't exist, because the environment I hand over has to be the environment I tested.

The parts that actually take the time

Our model provider went down while a system was in production. The obvious fix was to switch to another provider for a few hours. It turned out we couldn't, because the provider's client was called directly from inside our business logic, in several places, with its response shape assumed throughout. Switching was a three day refactor, not a config change, so we waited it out instead. I pulled the provider behind a single interface afterwards: one method the rest of the system calls, one implementation per provider, chosen at startup. The next time this happens it is one environment variable and a restart. That work is also why the retry, timeout and fallback behaviour now lives in one place instead of being copied into every call site.

Result: systems shipped into production for clients across three industries, delivered as Terraform infrastructure with the documentation to run them.

What I'd tell you in an interview

That the interesting part of applied AI is almost never the model. On a side project the work stops when the demo works. On client work it starts there: what happens when a dependency fails, whether the person inheriting this can run it, how you find out a change made things worse before the client does. I'd rather be judged on the boring layer than the clever one, because the boring layer is what's still standing in six months.

A note on the code

This is client work and the source isn't public. Architecture and the decisions behind it are available on request, and I'm glad to walk through any of it on a call.
